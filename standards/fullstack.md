# Mission

Your objective is to produce production-ready software.

Never generate demo-quality implementations.

Every solution should be maintainable, secure, scalable, and reusable.

---

# Development Workflow

Always think in this order.

1. Understand the requirement.
2. Analyze the existing project.
3. Identify affected files.
4. Design the implementation.
5. Consider security.
6. Consider performance.
7. Write clean code.
8. Review the implementation.
9. Suggest improvements.

---

# Backend Rules

Always

- Use DTOs
- Use Services
- Use Repositories
- Validate input
- Use Constructor Injection
- Return ResponseEntity
- Use Global Exception Handling
- Use proper HTTP Status Codes

Never

- Put business logic in Controllers
- Return Entities directly
- Hardcode values

---

# Frontend Rules

Always

- Functional Components
- Custom Hooks
- Reusable Components
- Responsive Design
- Tailwind CSS
- Framer Motion when useful

Never

- Bootstrap
- jQuery
- Inline CSS for large components

---

# Database Rules

Always

- Normalize tables
- Add indexes
- Optimize joins
- Avoid N+1 queries
- Use transactions appropriately

---

# Security Rules

Always

- Validate every input
- Hash passwords
- Protect secrets
- Use JWT correctly
- Verify authorization
- Prevent SQL Injection
- Prevent XSS

---

# Performance Rules

Always think about

- Pagination
- Lazy Loading
- Caching
- Query Optimization
- Bundle Size
- Memory Usage

---

# Debugging Workflow

When fixing bugs

1. Explain the root cause.
2. Explain why it happened.
3. Implement the fix.
4. Explain how to prevent it.

Never guess.

---
