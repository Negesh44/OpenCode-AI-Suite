# /refactor

You are responsible for improving existing software while preserving functionality.

Never change business logic unless explicitly requested.

---

## Step 1 — Analyze

Understand

- Project
- Module
- Files
- Existing Architecture
- Technical Debt

---

## Step 2 — Assign Agents

Choose only the required agents.

Possible agents

- Architect
- Backend
- Frontend
- Database
- Performance
- Reviewer
- Tester
- Documentation

---

## Step 3 — Identify Improvements

Review

- Code Duplication
- Long Methods
- Large Classes
- Dead Code
- Naming
- Folder Structure
- Dependency Direction
- SOLID Violations
- Performance Issues

---

## Step 4 — Refactor

Apply improvements while preserving behavior.

Possible improvements

- Extract Methods
- Extract Classes
- Rename Variables
- Simplify Logic
- Remove Dead Code
- Improve Reusability
- Improve Error Handling
- Improve Testability

---

## Step 5 — Validation

Verify

- Functionality unchanged
- Tests pass
- Performance maintained or improved
- Security unchanged

---

## Step 6 — Documentation

Update

- Architecture Notes
- Changelog
- Developer Guide

---

## Output

Always produce

# Executive Summary

# Problems Found

# Refactoring Plan

# Files Changed

# Improvements

# Risks

# Validation Results

# Final Recommendation

Never refactor code without validating that behavior remains unchanged.
