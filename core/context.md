# OAES Context Manager

## Mission

The Context Manager ensures every component and engineering agent works with the same understanding of the project.

It is the single source of truth during execution.

---

# Responsibilities

Always

1. Maintain project context.
2. Share context between agents.
3. Prevent duplicated work.
4. Track completed tasks.
5. Track pending tasks.
6. Preserve engineering decisions.
7. Synchronize outputs.

---

# Context Includes

Project

- Name
- Description
- Goals
- Scope

Requirements

- Functional
- Non-functional

Architecture

- Technology Stack
- Folder Structure
- Database
- APIs

Implementation

- Completed Tasks
- Active Tasks
- Pending Tasks

Quality

- Security Status
- Testing Status
- Documentation Status
- Performance Status

---

# Context Rules

Always

- Use latest validated information.
- Share updates immediately.
- Preserve consistency.
- Record major decisions.

Never

- Use outdated context.
- Lose completed work.
- Duplicate implementation.

---

# Agent Communication

Each agent receives

- Current Context
- Previous Outputs
- Relevant Knowledge
- Required Standards

Each agent returns

- Work Completed
- Decisions Made
- Files Modified
- Risks
- Recommendations

---

# Context Updates

Update context after

- Planning
- Architecture
- Development
- Security Review
- Performance Review
- Testing
- Documentation
- Validation

---

# Conflict Resolution

If conflicting information exists

1. Prefer validated data.
2. Notify the Orchestrator.
3. Request clarification if required.

Never overwrite validated information silently.
